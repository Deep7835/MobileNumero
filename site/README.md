# NumberKundli

A static, client-side website built from the *Advance Mobile Numerology Class* PDFs (modules 9–13).
No build step, no backend — everything runs in the browser.

## Run

```bash
python3 -m http.server 8765 --directory site
```

Then open http://localhost:8765. (Opening `index.html` directly also works.)

## Build, check, deploy

```bash
node tools/export-data.js         # exports per-birth-number data from the JS engine (run after editing data.js / numerology.js)
python3 tools/build.py            # regenerates blog + birth-number pages, hero images, favicon/OG images, sitemap.xml, robots.txt
python3 tools/check-links.py      # verifies every internal link/anchor; add --external to probe outside links too
python3 -m http.server 8765 --directory site
```

The canonical domain is **https://numberkundli.com** (set in `SITE_URL` in `tools/build.py` and `url` in `site/js/site-config.js`; `numberkundli.in` and `www.` redirect to it in every hosting config). If it ever changes, update both places and rebuild. Optional: add a GA4 or Plausible ID and a WhatsApp number in `site-config.js` (public values only — the site has no secrets and no backend).

Hosting configs are included for Netlify (`netlify.toml`, repo root), Vercel (`vercel.json`, repo root) and Apache (`site/.htaccess`): each forces HTTPS, serves `404.html` for missing pages and sets security/caching headers. `site.js` also redirects `http://` → `https://` client-side as a safety net (skipped on localhost).

## Lucky number generator, compare & share

`Numerology.generateNumbers(profile)` builds candidate 10-digit numbers per pattern (555 / 55 / 6 / 3 / 7 endings, repeating pairs, balanced mix) from the ideal-digit table, validates each with `analyzeMobile`, and keeps only numbers scoring ≥ 80 whose total is not an enemy of BN or DN. A seeded PRNG makes the suggestions stable per date of birth. `compareNumbers()` scores 2–3 candidates side by side. Share buttons use the Web Share API with a WhatsApp fallback.

## Birth-number landing pages

`tools/export-data.js` runs the real engine in Node and writes `tools/numbers.json`; `tools/build.py` turns it into `site/numbers/birth-number-1…9.html` (ideal digits, sample lucky numbers, PINs, password totals, wallpaper, covers, colours, affirmation, FAQ schema). Re-run the export after changing `data.js` or `numerology.js`.

## Blog

15 SEO articles live in `tools/posts.py` (content) and are rendered by `tools/build.py` into `site/blog/`. Each page has a unique title/meta, canonical URL, Open Graph + Twitter cards, `Article`, `BreadcrumbList` and `FAQPage` JSON-LD, a table of contents, internal links to related posts and the calculator CTA. Hero images (1200×630) are generated with Pillow — no stock photos, no licensing concerns. To add a post, append a dict to `POSTS` and rebuild.

## Algorithm (`numerology.js`)

- **Birth Number (BN)** — day of birth reduced to a single digit (29 → 11 → 2).
- **Destiny Number (DN)** — all DOB digits summed and reduced.
- **Lo Shu grid** — DOB digits + BN (if 2-digit day) + DN; missing numbers = energies to add via PIN/password.
- **Compatibility** — standard Chaldean friendly / enemy / neutral chart (`DATA.friendly`); *balancer* numbers are friendly to both BN and DN.
- **Mobile number analysis** — last 10 digits; each digit checked against `DATA.digitRules` (digit × position → good/bad + weight), whole-number patterns (`555`, `55`, `000`, ends with 8…), total reduced and compared with BN/DN. Score starts at 70, ±weights, ±compatibility, clamped 0–100.
- **PIN generator** — enumerates 4-digit combinations from non-enemy digits, keeps only those whose total is friendly to both BN and DN, ranks by missing-number coverage. `checkPin` scores any 4–6 digit PIN.
- **Chaldean calculator** — letter values from `DATA.chaldean`; total mapped to purpose (`DATA.passwords`).
- **Recommendations** — wallpaper (BN & DN), cover (best-for birth numbers), phone colour (planet number vs BN), affirmation/ringtone/mantra (BN & DN).

## Languages

The site is available in English, Hindi, Marathi, Tamil and Gujarati (🌐 selector in the nav bar; the choice is remembered and defaults to the browser language).

- **UI strings** live under `ui` in each pack and are looked up by key with `t('key', {vars})`. Static HTML uses `data-i18n`, `data-i18n-html`, `data-i18n-ph` (placeholder) and `data-i18n-title` attributes.
- **Content strings** (position rules, cover traits, wallpapers, affirmations, purposes…) stay in English in `js/data.js` as the source of truth; each pack's `data` map translates them by exact English text via `td(text)`. Anything not in a pack falls back to English, so a missing translation never breaks the page.
- Indic scripts use Noto Sans Devanagari / Tamil / Gujarati from Google Fonts; `I18N.LANGS` sets `--font` / `--display` per language.
- The PDF report is fully translated (it renders with the same webfonts). The disclaimer and page numbers in the PDF's bottom margin are drawn by jsPDF, which only ships Latin fonts, so those two lines stay in English.
- The translations were produced by an AI model, not a native-speaker translator — have a native speaker review `js/lang/<code>.js` before publishing; each entry is a plain `'English': 'translation'` pair.

### Multilingual blog

All 15 articles exist in all five languages (75 pages) at `blog/` (English), `hi/blog/`, `mr/blog/`, `ta/blog/` and `gu/blog/`. Translations live in `tools/posts_<lang>.py` keyed by slug (title, meta, excerpt, body, faqs, label) and are rendered by `tools/build.py`, which also:

- emits `hreflang` alternates (+ `x-default`) on every post and index, in the HTML and in `sitemap.xml`;
- sets `<html lang>`, `og:locale`, localized page chrome (nav, breadcrumbs, dates, "min read", FAQ heading, footer) from the `UI` table in `build.py`;
- generates a localized hero image per post (`assets/blog/<slug>-<lang>.{webp,jpg}`). Pillow cannot shape Indic scripts, so `tools/native_text.py` renders the title and label through macOS CoreText (PyObjC) and composites them in — on a non-Mac build host these images would need another shaping engine (e.g. Pillow built with libraqm);
- adds a language switcher to every article, and links back to the home page with `?lang=xx` so the calculator opens in the same language.

## PDF report

The **Download your report** section exports everything as an A4 PDF:

- **Download PDF** — `Report.download()` renders a self-contained, light-themed report (`Report.build()`) inside the page behind an overlay and converts it with [html2pdf.js](https://github.com/eKoopmans/html2pdf.js) (loaded from cdnjs on first click, ~300 KB). The file is named `<name>-mobile-numerology-report.pdf`.
- **Print / Save as PDF** — opens the same report in a new tab and calls `window.print()`; works fully offline.
- **Preview** — opens the report in a new tab without printing.

Report CSS is scoped under `.rpt` so the site's styles never leak into the PDF. Each `<h2>` is grouped with the block after it (`page-break-inside: avoid`) so headings are never orphaned, the disclaimer and page numbers are drawn by jsPDF into every page's bottom margin, and the capture uses `scrollX/scrollY: 0` (the host is `position: fixed`) — do not pass `windowWidth`, it shifts the crop.

To tweak any rule or weight, edit `js/data.js` only.
